RAG

Retrieve, then generate

▶ Open the interactive version (diagrams, labs, quizzes)

Stale knowledge, missing private knowledge, hallucination, and answers you can’t trace.

Models go stale and invent. Open-book: retrieve, then generate.

  • Chunk docs into blocks and embed them.
  • Embed the question, fetch top chunks into the prompt.
  • The model answers looking at the evidence.
  • Don’t make it memorise — make it an open-book exam: retrieve material, put it in the prompt, then answer. Knowledge in the weights and in an outside store work together.
  • Pipeline: ① chunk the documents (a few hundred tokens each, with some overlap) ② embed each chunk into a vector store (“Word vectors” again) ③ embed the question and take the top-k by cosine similarity (approximate nearest-neighbour indexes such as HNSW at scale, often mixed with keyword search like BM25) ④ re-rank with a cross-encoder — coarse first, then fine ⑤ the prompt says “answer only from these sources and cite them”.
  • Chunks too big retrieve poorly; too small lose context.
  • Chunk → embed → retrieve → rerank → generate.
  • Leave policy chunk 0.82 > expense chunk 0.31.
  • Question: “What is the company’s 2026 annual-leave policy?”
  • Cosine 0.82 with the “staff handbook — leave” chunk, 0.31 with “expense claims”; the first goes into the prompt and the answer cites it.
  • top-k cosine(question, chunk)
  • retrieve: top-k cosine(question vector, chunk vectors) → re-rank → into the prompt → generate
  • No weight update — only the prompt changes

Left open RAG only solves “knowing”. People also want it to do things: fetch live data, calculate, edit code, send email — and multi-step questions need looking things up while thinking.

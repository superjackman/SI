Build an agent

A no-code platform or code: either way you build the think → tool → think loop.

No code: drag it on a platform; code: write the loop with an SDK; fixed steps: use a workflow.

Why it’s designed this way: Once you know the loop, you understand what any agent product does.

▶ Open the interactive version (tap the diagram, try labs, take the quiz)

🧒 In plain words

📏 Covered here: the two roads to an agent (no-code platforms, code), the real platforms and frameworks on each, what the smallest agent loop looks like, and how to test before launch. Not covered: training models, platform prices, or signing up for overseas services.

Building an agent is like making a little assistant that looks things up: it thinks, looks something up if needed (a tool), thinks again, and answers when it can.

📑 What this stop covers

  • 🛠 Build your own agent: two roads
    Every agent runs the same small loop: the model thinks → runs a tool if needed → the result goes back → it thinks again, until it can answer. You can drag this loop together on a…
  • 🧩 Road 1: no-code / low-code platforms
    A no-code platform is like building with blocks: pick a model, write instructions, add tools and documents, and publish without a line of code.
  • ⌨️ Road 2: an agent loop in 25 lines
    In code, the model only says “please use this tool”; your program actually runs it, hands back the result, and the model thinks again.
  • ✅ Before launch: give it an exam
    Before launch it is like a driving test: 10 questions asked again and again, a limit on steps and spending, and a log of every step.
  • ⚠️ Easy to mix up: workflow vs agent
    A workflow is like a bus: fixed route, on time, cheap; an agent is like a taxi: the driver picks the way, flexible, but may detour and costs more.

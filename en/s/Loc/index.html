Run models locally

Will it fit, which runner, which file.

Running locally: download an open-weights model and run it on your own computer; data stays home and there is no per-token bill, but it must fit in memory.

Why it’s designed this way: Privacy, working offline, or wanting to tinker all lead here.

▶ Open the interactive version (tap the diagram, try labs, take the quiz)

🧒 In plain words

📏 Covered here: how big a model your computer can run, which tools to use, where to download, how to read file names. Not covered: training models, or reaching overseas sites.

Running locally is like inviting a chef to your home: the ingredients (your data) never leave, and there is no per-dish bill; but the kitchen (memory) must be big enough, and the chef is usually not as good as a top restaurant (the largest cloud models).

📑 What this stop covers

  • 💻 Running locally: the model computes on your own computer
    Models with “open weights” can be downloaded and run on your own computer or server, without calling someone else’s API.
  • 🧮 Will it fit: estimating memory
    The model has to be loaded into memory to run. Size ≈ number of parameters × bits each ÷ 8, plus the “scratch paper” the chat uses (the KV cache). 8 billion parameters at a…
  • 🧰 Four common runners

  • 📦 Where to download, and what
    Where to download? In China, use ModelScope or the hf-mirror mirror. Pick the “Instruct” (chat) version, and check the licence before use to see whether commercial use is allowed.
  • 🏷️ Reading file names: GGUF and Q4_K_M
    A model file name is like a product label: 8B is “how big”, Instruct is “chats well”, Q4_K_M is “how many bits, which method, medium size”, and .gguf is “which format”.
  • ⚠️ Easy to mix up: file size vs memory while running
    The downloaded file is only the “recipe”; actually cooking needs plates and scratch space (the KV cache). So memory while running is bigger than the file, and grows with the chat.

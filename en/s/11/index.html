Cheap adaptation

LoRA, quantisation

▶ Open the interactive version (diagrams, labs, quizzes)

Full fine-tuning stores gradients and optimiser state for every parameter: with mixed precision + Adam, roughly 16 bytes per parameter rough estimate, so a 7B model needs about 112 GB before activations — and every task keeps its own full copy.

Full fine-tuning is costly. LoRA trains a thin side path; quantisation stores fewer bits.

  • Freeze W; add B×A beside it.
  • Quantisation shortens each number.
  • LoRA (Hu et al., 2021): the change ΔW from fine-tuning tends to be low-rank empirical, so freeze W and learn two thin matrices B and A. Afterwards B × A merges back into W at no inference cost; each task keeps only its small matrices.
  • SVD intuition: a matrix = U × Σ × V^T; keeping the r largest singular values gives the best rank-r approximation.
  • Quantisation: store weights in fewer bits. FP16 is 2 bytes per parameter, INT8 1, INT4 0.5; some accuracy is lost and must be measured.
  • QLoRA (Dettmers et al., 2023): keep the base model in 4 bits and train LoRA on top, so one GPU can fine-tune a fairly large model.
  • Frozen W ∥ side path B×A; or INT4 weights.
  • The full matrix holds 4096 × 4096 = 16,777,216 numbers; the side path trains 2 × 4096 × 8 = 65,536, about 0.39%. Memory for seven billion parameters, by bit width: 16 bits (FP16) ≈ 14 GB, 8 bits ≈ 7 GB, 4 bits (INT4) ≈ 3.5 GB parameters only, plus a few scale values.
  • Same as card : a 4096 × 4096 matrix: full fine-tuning changes 4096 × 4096 = 16,777,216 parameters; LoRA with r = 8 trains only 2 × 4096 × 8 = 65,536, about 0.39%.
  • A 7-billion (7B) parameter model: 16 bits (FP16) ≈ 14 GB, 8 bits ≈ 7 GB, 4 bits (INT4) ≈ 3.5 GB parameters only, plus a few scale values.
  • W′ = W + BA
  • x ≈ q × s
  • W′ = W + B × A, B is d × r, A is r × k, r ≪ d, k
  • Quantise: q = round(x / s), restore x ≈ q × s (s is often per group or per channel)
  • frozen W
  • low-rank update
  • fewer bits

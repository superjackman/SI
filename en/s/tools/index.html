Same job, real differences

Host a desk that retrieves your documents

  1. The first step is not the same. Dify’s README calls Docker Compose the easiest start and lists at least 2 CPU cores and 4 GiB of RAM. RAGFlow’s README, in the Docker section, recommends starting at 4 cores, 16 GB of RAM and 50 GB of disk, and checks out tag v1.0.0. Flowise’s README quick start is Node.js 20 or newer, then npx flowise start, on port 3000. Docker is a second path.
    • https://github.com/langgenius/dify/blob/main/README.md
    • https://github.com/infiniflow/ragflow/blob/main/README.md
    • https://github.com/FlowiseAI/Flowise/blob/main/README.md
  2. The licenses differ. Dify’s LICENSE adds conditions on top of Apache 2.0: no multi-tenant service from the source without written permission, and frontend logo and copyright notices stay. RAGFlow’s LICENSE file is the Apache 2.0 text. Flowise’s LICENSE.md puts the enterprise directory under a commercial license and the rest under Apache 2.0. Public code is not unconditional commercial use.
    • https://github.com/langgenius/dify/blob/main/LICENSE
    • https://github.com/infiniflow/ragflow/blob/main/LICENSE
    • https://github.com/FlowiseAI/Flowise/blob/main/LICENSE.md
  3. The first screen in the docs is not the same. Dify’s docker/README says to open http://localhost/install and create an administrator. RAGFlow’s README says that after healthz returns HTTP 200 you sign in in the browser, then add an LLM, an embedding model and a reranker, including an API key. Flowise’s README says to open http://localhost:3000 after start. This page did not run those installs.
    • https://github.com/langgenius/dify/blob/main/docker/README.md
    • https://github.com/infiniflow/ragflow/blob/main/README.md
    • https://github.com/FlowiseAI/Flowise/blob/main/README.md

Same job, real differences

Run a model on your own computer

  1. The docs give different programs the job of running the model. Ollama’s quick start is ollama run gemma4:e2b, and it says that download is about 7.2 GB, with 8 GB of VRAM or Mac unified memory recommended. LM Studio’s docs describe a desktop app that runs GGUF through llama.cpp, and MLX on Apple silicon. llama.cpp’s README quick start is llama cli or llama serve, with the example ggml-org/Qwen3.5-0.8B-GGUF. vLLM’s quick start, on Linux, is vllm serve Qwen/Qwen2.5-1.5B-Instruct, at http://localhost:8000, one model at a time. Open WebUI’s README describes a browser screen that connects to Ollama or an OpenAI-compatible API. The image tag :ollama bundles Ollama; :main does not.
    • https://docs.ollama.com/quickstart
    • https://lmstudio.ai/docs/app
    • https://github.com/ggml-org/llama.cpp/blob/master/README.md
    • https://docs.vllm.ai/en/latest/getting_started/quickstart/
    • https://github.com/open-webui/open-webui/blob/main/README.md
  2. The licenses differ. The LICENSE files for Ollama and llama.cpp are MIT. vLLM’s LICENSE is Apache 2.0. Open WebUI’s LICENSE allows redistribution and limits removing the brand: above 50 end users in any rolling 30 days, removing the brand needs written permission or an enterprise license. No public repository LICENSE was found for LM Studio. On 2026-11-07, https://api.github.com/repos/lmstudio-ai/lmstudio returned 404. The site terms grant personal and internal business use, and call the software and its source code trade secrets. Public code and commercial use are not the same thing. LM Studio’s source was not offered as a public repository.
    • https://github.com/ollama/ollama/blob/main/LICENSE
    • https://github.com/ggml-org/llama.cpp/blob/master/LICENSE
    • https://github.com/vllm-project/vllm/blob/main/LICENSE
    • https://github.com/open-webui/open-webui/blob/main/LICENSE
    • https://lmstudio.ai/terms
  3. The machines in the docs are not the same. Ollama’s quick start ties gemma4:e2b to a download of about 7.2 GB and 8 GB of VRAM, and says that with less VRAM it can use system RAM, with slower replies. LM Studio’s system-requirements page says a Mac needs Apple silicon and macOS 14.0 or newer, recommends 16GB or more of RAM, and says Intel Macs are not supported for now. On Windows it recommends at least 16GB of RAM and 4GB of dedicated VRAM. vLLM’s quick start lists Linux and Python 3.11 through 3.14, and says macOS is the separate vLLM-Metal path, not that page’s default install. Open WebUI’s pip install says it requires Python 3.12.
    • https://docs.ollama.com/quickstart
    • https://lmstudio.ai/docs/app/system-requirements
    • https://docs.vllm.ai/en/latest/getting_started/quickstart/
    • https://github.com/open-webui/open-webui/blob/main/README.md

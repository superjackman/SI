Site

Suits

You want the README’s commands: run a GGUF model on your machine, or serve an OpenAI-compatible API from that machine.

Not for

You only want an installer with no commands, and you do not want the build guide. The README points a from-source build at a separate build guide. Pre-built binaries are on the releases page.

Smallest first step

The README quick start lists an install script, https://llama.app, Docker, pre-built binaries from the releases page, or a from-source build via the build guide. After that, the examples are llama cli -hf ggml-org/Qwen3.5-0.8B-GGUF and llama serve -hf ggml-org/Qwen3.5-0.8B-GGUF.

What the docs say you see

The README captions two pictures: a VLM session with llama cli, and the built-in web UI of llama serve running Qwen 3.6. This page does not transcribe the words in those pictures. It also did not run the two commands.

What it takes to run

The README says inference is in C/C++, lists backends including CUDA, HIP, Vulkan and SYCL, and mentions CPU plus GPU hybrid inference. The quick start does not give one shared minimum for memory. The model file is a GGUF you download separately.

A failure the docs name

The performance troubleshooting page says that GPU use depends on compiling with the environment variables in the build guide, so that -ngl is accepted. It tells you to look for lines beginning llama_model_load_internal: [cublas] offloading. Those lines are how it says the GPU is in use. The same page says that if generation is extremely slow, try -t 1. If that is much faster, the CPU is oversaturated. That page still writes the command as ./llama-cli, which is not the same spelling as llama cli in the README quick start. Both pages were opened on 2026-11-07.

Same job, real differences

Run a model on your own computer

  1. The docs give different programs the job of running the model. Ollama’s quick start is ollama run gemma4:e2b, and it says that download is about 7.2 GB, with 8 GB of VRAM or Mac unified memory recommended. LM Studio’s docs describe a desktop app that runs GGUF through llama.cpp, and MLX on Apple silicon. llama.cpp’s README quick start is llama cli or llama serve, with the example ggml-org/Qwen3.5-0.8B-GGUF. vLLM’s quick start, on Linux, is vllm serve Qwen/Qwen2.5-1.5B-Instruct, at http://localhost:8000, one model at a time. Open WebUI’s README describes a browser screen that connects to Ollama or an OpenAI-compatible API. The image tag :ollama bundles Ollama; :main does not.

  3. The machines in the docs are not the same. Ollama’s quick start ties gemma4:e2b to a download of about 7.2 GB and 8 GB of VRAM, and says that with less VRAM it can use system RAM, with slower replies. LM Studio’s system-requirements page says a Mac needs Apple silicon and macOS 14.0 or newer, recommends 16GB or more of RAM, and says Intel Macs are not supported for now. On Windows it recommends at least 16GB of RAM and 4GB of dedicated VRAM. vLLM’s quick start lists Linux and Python 3.11 through 3.14, and says macOS is the separate vLLM-Metal path, not that page’s default install. Open WebUI’s pip install says it requires Python 3.12.

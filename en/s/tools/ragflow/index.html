RAGFlow

Open source: a document engine for retrieval-augmented generation, self-hosted.

The repository LICENSE is Apache 2.0; commercial use keeps its notice terms

Not measured from mainland China

Site

Suits

You want to host document parsing and retrieval yourself, and you can meet the README’s suggested start: 4 cores, 16 GB of RAM, 50 GB of disk, Docker 24.0.0 or newer, and Compose v2.26.1 or newer.

Not for

The machine is well under that suggested start, or you cannot install Docker. The README also says the real need depends on the document engine, data volume, parsing tasks and concurrency, and that local models and other optional parts may need more.

Smallest first step

The README’s start order: clone the repo, enter ragflow/docker, check out v1.0.0, and run docker compose -f docker-compose.yml up -d. After dependencies show healthy and the RAGFlow container is still running, run curl -f http://localhost/api/v1/system/healthz. After HTTP 200, open the web UI. The default is http://YOUR_MACHINE with no port, because the default port is 80. After signing in, add an LLM, an embedding model and a reranker, including the model name, service address and API key.

What the docs say you see

The README’s ready signal is HTTP 200 from healthz, then the sign-in page. It does not paste a reply from after sign-in. This page did not run that deployment.

What it takes to run

README: a suggested start of 4 CPU cores, 16 GB of RAM and 50 GB of free disk; Docker 24.0.0 or newer and Docker Compose v2.26.1 or newer. If you use Elasticsearch, set vm.max_map_count on the Docker host to at least 262144. With Infinity that step is usually unnecessary.

A failure the docs name

The README says the RAGFlow container itself does not define a Compose healthcheck. If startup fails, it tells you to read docker logs --tail 50 ragflow-cpu. If you use Elasticsearch and vm.max_map_count is below 262144, it says to raise that value first.

Same job, real differences

Host a desk that retrieves your documents

  1. The first step is not the same. Dify’s README calls Docker Compose the easiest start and lists at least 2 CPU cores and 4 GiB of RAM. RAGFlow’s README, in the Docker section, recommends starting at 4 cores, 16 GB of RAM and 50 GB of disk, and checks out tag v1.0.0. Flowise’s README quick start is Node.js 20 or newer, then npx flowise start, on port 3000. Docker is a second path.

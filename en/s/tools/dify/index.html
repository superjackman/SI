Dify

Open source: a self-hosted desk for retrieval and agents.

Modified Apache 2.0; multi-tenant use needs a commercial license

Not measured from mainland China

Site

Suits

You want a retrieval and agent desk on your own machine with Docker, and the machine meets the README minimum of 2 cores and 4 GiB of RAM.

Not for

You want to run a multi-tenant service from this source (the LICENSE says one tenant is one workspace) without written permission, or you want to remove the frontend logo and copyright notices.

Smallest first step

The README’s new deployment: from the repo, enter docker, copy .env.example to .env, generate a token with OpenSSL, and have Docker running with Docker Compose v2.35.0 or later. docker/README then says docker compose up -d, and open http://localhost/install. The self-host docs also say the Docker Desktop virtual machine on macOS needs at least 2 virtual CPUs and 8 GiB of memory.

What the docs say you see

docker/README says the result is the browser at http://localhost/install for the initial setup, then signing in at http://localhost. The default HTTP port is 80. This page did not start those containers, so it does not quote a screen from after sign-in.

License

The repository LICENSE calls itself a modified Apache 2.0. The multi-tenant rule and the frontend logo rule are extra conditions. The other rights and restrictions follow Apache 2.0. The README license section says the repo uses the Dify Open Source License, based on Apache 2.0 with additional conditions. Public code is not unconditional commercial use.

What it takes to run

README: at least 2 CPU cores and 4 GiB of RAM, a running Docker daemon, Docker Compose v2.35.0 or later, and OpenSSL. The self-host docs repeat that CPU and RAM minimum.

A failure the docs name

A row in the docker/README troubleshooting table says the Python sandbox returns operation not permitted. The same row says sandbox 0.2.15 restricts the epoll_pwait syscall when networking is disabled, on both ARM64 and AMD64, and that the runtime failure has been reproduced on ARM64.

Same job, real differences

Host a desk that retrieves your documents

  1. The first step is not the same. Dify’s README calls Docker Compose the easiest start and lists at least 2 CPU cores and 4 GiB of RAM. RAGFlow’s README, in the Docker section, recommends starting at 4 cores, 16 GB of RAM and 50 GB of disk, and checks out tag v1.0.0. Flowise’s README quick start is Node.js 20 or newer, then npx flowise start, on port 3000. Docker is a second path.
    • https://github.com/langgenius/dify/blob/main/README.md
    • https://github.com/infiniflow/ragflow/blob/main/README.md
    • https://github.com/FlowiseAI/Flowise/blob/main/README.md
  2. The licenses differ. Dify’s LICENSE adds conditions on top of Apache 2.0: no multi-tenant service from the source without written permission, and frontend logo and copyright notices stay. RAGFlow’s LICENSE file is the Apache 2.0 text. Flowise’s LICENSE.md puts the enterprise directory under a commercial license and the rest under Apache 2.0. Public code is not unconditional commercial use.
    • https://github.com/langgenius/dify/blob/main/LICENSE
    • https://github.com/infiniflow/ragflow/blob/main/LICENSE
    • https://github.com/FlowiseAI/Flowise/blob/main/LICENSE.md
  3. The first screen in the docs is not the same. Dify’s docker/README says to open http://localhost/install and create an administrator. RAGFlow’s README says that after healthz returns HTTP 200 you sign in in the browser, then add an LLM, an embedding model and a reranker, including an API key. Flowise’s README says to open http://localhost:3000 after start. This page did not run those installs.

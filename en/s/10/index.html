Post-training: SFT + RL

SFT, RLHF/DPO, reasoning RL

▶ Open the interactive version (diagrams, labs, quizzes)

The problem Make it follow instructions, be helpful and safe — and learn to think before answering.

Why care

A base model only continues text. Post-training makes it follow instructions, stay safer, and think before answering.

Everyday analogy

  • SFT learns format from demos.
  • RLHF / DPO steer with preferences.
  • Reasoning RL grows long chains of thought on checkable tasks.

Core idea

  • SFT: keep training with the same next-token loss on “instruction → good answer” demonstrations (usually only the answer counts), teaching the chat format and style.
  • RLHF: comparing two answers is easier for people than writing a perfect one. Train a reward model on preference pairs, then use RL (e.g. PPO) to maximise reward, with a KL penalty so it doesn’t drift far from the original or game the reward model.
  • DPO (Rafailov et al., 2023): the KL-constrained objective has a closed-form optimum, so you can skip the reward model and RL and train on preference pairs directly — simpler and more stable.
  • Reasoning models (the main direction since 2024): RL on tasks whose answers can be checked automatically (maths has answers, code has tests), rewarding only a correct final answer; models learn to write long chains of thought — break down, try, check, backtrack. Some labs don’t publish details; among published methods, GRPO was introduced in DeepSeekMath (2024) and DeepSeek-R1 (2025) also trains reasoning with it.

Formula

  • P(A>B)=σ(r_A−r_B)
  • DPO: prefer pairs directly, skip the reward model
  • Reward model (Bradley-Terry): P(A beats B) = σ(r_A − r_B)
  • RLHF objective: reward r − β × KL(current ‖ reference)
  • DPO: loss = − log σ(β × [log(π(good)/π_ref(good)) − log(π(bad)/π_ref(bad))])
  • Pipeline: pre-training (knowledge) → SFT (format) → preference alignment / RL (preferences and reasoning)

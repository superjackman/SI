让它自己干

交出去，它独立跑完，你事后验收。

后台 / 云端 Agent、例程与自动化、多 Agent 协作：没人在旁边看着，靠隔离、可检查的产出和人来按最后一步保证安全。

为什么这样设计：说得清、能验收的活不需要你一直在场；把你的时间留给审查和拍板。

▶ 打开互动版（能点图、做实验、做小测）

🧒 先用大白话说

“让它自己干”就像把作业交给别人做、你回头再检查。没人在旁边看着，所以要靠三样东西保平安：让它在不会弄坏东西的地方干活；交回来的东西能检查；撤不回的那一步（合并、发送、付钱）由你来按。

📑 这一站讲了什么

  • 让它自己干：交出去，事后验收
    这一类用法里，Agent 没有人在旁边看着。所以安全不能靠“你随时喊停”，要靠三样东西：
  • ☁️ 后台 / 云端 Agent
    后台助手像请人在另一间屋子里干活：你写好任务交出去，它在网上的一台单独机器里改代码、跑测试，最后交回一份“改动清单”（PR）等你看。适合说得清、能检查、不着急的活。
  • ⏰ 例程与自动化
    例程就像定好的闹钟：到点了或者来了新邮件，助手就按写好的说明自动做一遍。会“发出去”的事先只写草稿，人看过再发；同一件事做两遍也只算一次；每次做了什么都记下来。
  • 👥 多 Agent 协作
    多个助手合作像小组作业：组长把大题拆开，分给几个组员各做一块，最后有人检查、汇总。几个人同时做，时间省了，但花费更多；给组员的任务要写清楚，因为他们听不到组长和你说过的话。
  • 🧠 为什么交回的是“PR”，而不是直接改好？
    为什么交回“改动清单”而不是直接改好？就像作文先给老师看，不直接贴到墙上：最坏的情况只是“不用”，什么都没坏；改动和测试结果摆在一起，检查比自己重做快得多。
  • 🤔 什么时候才值得上多 Agent？
    人多不一定力量大。研究发现，好几个助手一起干活时常常配合不好，失败的不少，比一个助手强不了多少，花费却多很多。只有能拆成互不相干的几块、每块要读很多资料的活，才值得试。
  • 🔎 “深度研究”是怎么做出来的
    “深度研究”像派几个同学分头去图书馆查资料：一个人定计划，几个人各查一个方向，回来汇总，不够再查一轮，最后把每句话标上出处。拿到报告后要自己点开几个出处看看，原文是不是真这么说。
  • 🛤️ 工作流还是 Agent？同一件事做两遍
    “工作流”像照着菜谱做菜，每一步都写死了，每次都一样，出错也好找；“Agent”像请厨师自己看着办，更灵活，但每次花的时间和结果可能不同。能先写好步骤的事，用菜谱更稳。
  • 🧪 一个 vs 一群：拆给几个子 Agent (动手实验)
  • 🧪 做一个例程：模拟一周 (动手实验)

应用实战

编程助手、研究、电脑操作、端侧

▶ 打开互动版（能点图、做实验、做小测）

要解决的问题 把前面各站拼起来：现在这些能力都用在哪？

为什么要关心

学完原理，最想知道的是：现在能用来干嘛？ 答案是把前面的站拼起来。

生活类比

  • 编程助手像带测试的学徒：改代码、跑测试、失败再改。
  • 深度研究像开卷考试：边查边写，还标出处。
  • 电脑操作像远程桌面：看截图、点按钮。
  • 每一种都能拆回前面的站，而不是魔法。

核心思想

  • 编程助手：代码预训练 + 测试做可验证奖励 + 检索代码库（RAG）+ Agent 循环读改跑修。
  • 深度研究：多步检索、引用出处、长上下文；原理回指第 13、15b 步。
  • 电脑 / 浏览器操作：截图当视觉词元（15a）+ 工具调用（14）。
  • 蒸馏与端侧：大模型教小模型，量化后在手机上跑（第 11、12 步）。不写会过期的产品排行榜。

看图在说什么

  • 用户目标 → 选用站（RAG / 工具 / 多模态 / 推理）→ 办完事。

算一算

  • 同一条修 bug 链：检索 → 编辑 → 测试 → 循环。
  • 「修这个报错」→ 读代码（RAG）→ 改 → 跑测试（工具）→ 失败再改（Agent）（KA08 卡同一思路）。
  • 每一步都能指回本站前面某一站。

公式

  • 应用 = 编排(预训练, RAG, 工具, 多模态, 推理时计算)
  • 场景 → 用到的站：预训练 / RAG / 工具 / 多模态 / 推理时计算
  • 不背产品名，背类型和对应的站

留下的问题 可靠性、安全、评估、成本仍是开放问题。具体产品按月变，请以最新资料为准。

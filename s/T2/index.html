Agent

Agent = 大模型 + 一个循环程序。

Agent = 大模型 + 一个循环程序：模型写出“要调用哪个工具”，程序去执行，再把结果喂回模型，直到事情办完。

为什么这样设计：模型本身只会写字，不能上网、不能改日历；所以需要程序替它动手，并替你把关。

▶ 打开互动版（能点图、做实验、做小测）

🧒 先用大白话说

大模型就像一个只会动嘴、不会动手的聪明人：它能想、能写，但自己上不了网，也按不了按钮。Agent 是陪在它身边的小助手程序：大模型说“去查一下天气”，助手就真的去查，再把结果念给它听，它再想下一步。这样一圈一圈转，直到事情办完。

📑 这一站讲了什么

  • Agent：让大模型“动手干活”的那层程序
    大模型只会“写字”。Agent 应用层让它写的字变成真实的动作：观察 → 思考 → 调用工具 → 看结果 → 再思考，直到完成。图中“③ 思考/决策”就是大模型…
  • 🧪 一步步走完 Agent 循环
    按“下一步”，跟着助手一圈一圈地走：看一看、想一想、动手、看结果，再想。上面图里正在干活的方块会亮起来。
  • 🔧 工具调用：模型其实只是“填了一张 JSON 表”
    大模型“用工具”，其实只是填了一张表：写清楚要用哪个工具、填什么内容。真正去做事的是程序；程序会先检查这张表填得对不对，填错了就退回去让它重填。下面可以改一改这张表试试。
  • ⚠️ 容易混淆：大模型 vs Agent
    大模型像一个只会说话的大脑；Agent 是给它配上手脚的程序：大脑说“去查天气”，程序真的去查，再把结果告诉大脑。
  • 📚 记忆 / RAG：先查资料，再回答
    大模型记不住你家的私事，也不知道今天的新闻。办法像开卷考试：先从资料里翻出最相关的几段，夹在问题旁边一起交给它，它就能照着资料回答，还能说出出处。
  • ⚠️ 容易混淆：上下文 vs 记忆/RAG vs 微调
    模型只能看见这一次放在它面前的文字（上下文）。“记忆”和“查资料”是把东西存在外面，要用时再摆到它面前；只有“微调”才是真正把东西学进脑子里。
  • 🗺️ 规划：先拆步骤
    大事要拆成小步，就像做蛋糕：先买材料，再搅面糊，最后才能烤。有的步骤必须等前一步做完才能做，比如先知道会不会下雨，才知道要不要提醒带伞。
  • 👥 多 Agent 协作
    同一个大模型，换上不同的“工作说明”和工具，就能扮演不同的角色，像一个小组里有人干活、有人检查。但人多不一定更好：传话会漏信息，也更花钱。
  • 🔌 MCP / 工具协议：工具的“统一插座”
    MCP 就像统一的插座：以前每个应用要给每个工具单独做一根线；有了统一插座，工具做一个插头、应用装一个插座，就都能连上。
  • 🛡️ 评估与风险
    助手会真的动手，所以要装好门锁：只给它干这件事需要的最少权限；发邮件、付钱这类重要的事，先问你。网页里也可能藏着骗它的坏话，下面的小实验可以看看防护开和关有什么不同。
  • 🧠 底层逻辑
    为什么要“走一步、看一步”？一次就把复杂的事做对很难，但每走一步都能看到结果：出错了能发现、能改。就像走迷宫，碰到墙就换条路。代价是每转一圈都要再问一次大模型，更慢也更花钱…
  • 🧾 结构化输出：让每个 token 都“合法”
    程序只看得懂格式整齐的表。所以大模型每写一小块字（token），都会先把不合格式的选项划掉，只在合格的里面挑，像填空题只能填数字的格子里不让写字。
  • 🎯 召回 → 重排 → 引用：检索的两段式
    找资料分两步，像先海选、再决赛：第一步用快办法从一大堆里挑出几十条可能有用的；第二步用更细心但更慢的办法，一条条和问题对照着重新排名，只把最前面几条交给大模型，并要求它注明出处。
  • 🤝 A2A：Agent 和 Agent 怎么说话
    MCP 让助手接上工具；A2A 让助手和别的助手说话：互相介绍自己会干什么、分派任务、取回结果，就像两家公司的接待员对接工作，彼此不用知道对方内部怎么干。
  • 🧪 Agent 沙盒：选任务、开关工具，看循环怎么随机应变 (动手实验)
  • 🧪 提示词注入攻防：一层层加防护 (动手实验)
  • 🧪 RAG 小游乐场：先查资料再回答 (动手实验)

工具与 Agent

函数调用、Agent 循环、MCP

▶ 打开互动版（能点图、做实验、做小测）

要解决的问题 让模型与外部世界交互，完成多步任务。

为什么要关心

只会说不够，还要会做：查天气、改日历。模型只写调用，程序去执行。

生活类比

  • 工具说明先给模型看。
  • 它输出调用 JSON，程序执行，结果写回。
  • 循环：观察→想→做→再观察，直到停。

核心思想

  • 工具调用：把工具说明（名称、参数的 JSON Schema）告诉模型，它在需要时输出结构化请求，例如 {"name": "get_weather", "arguments": {"city": "上海"}}；由程序执行，结果放回上下文。模型自己不执行任何东西，只决定调用什么。
  • Agent 循环：观察 → 思考 → 行动 → 看结果 → ……直到完成（ReAct，Yao 等，2022）。再加上规划（拆子任务）、记忆（上下文是短期，外部库是长期）、反思（跑测试、对照目标，出错重试）。
  • MCP：Anthropic 于 2024 年 11 月发布的开放协议，基于 JSON-RPC 2.0、客户端-服务器结构，统一地向模型应用暴露工具、资源和提示模板，把“M 个应用 × N 个工具”的对接变成 M + N。
  • 难点：误差累积、权限与安全（提示注入、越权，对策是最小权限、沙箱、敏感操作人工确认、区分指令与数据）、评估和成本。多智能体分工有时有帮助，但不总是比单个 Agent 好。

看图在说什么

  • 观察 → 思考 → 行动 → 观察 … → 完成/问人。

算一算

  • 下雨则改会议：天气→日历→确认→更新，约 4 次调用。
  • “明天上海下雨的话，把我的户外会议改到线上。”
  • 天气工具（降雨概率 80%）→ 日历工具找到会议 → 生成修改 → 请用户确认 → 日历更新工具。共 4 次工具调用，其中 1 次是人工确认节点。

公式

  • 0.95^20 ≈ 0.36：步数一多要校验
  • 每步成功率 95% 时，20 步全成功的概率 = 0.95^20 ≈ 0.36
  • 模型不当执行者；权限与确认见安全站

留下的问题 会调工具了。下一步专门谈安全：注入、越狱、权限与确认。

给它装本事

工具、MCP、Skills：不换模型，多会几样。

工具给它新动作，MCP 让它接上别人做好的工具，Skills 给它按需加载的做法说明。它们的说明都要占上下文。

为什么这样设计：改模型又贵又慢；在外面给它说明书和手脚，当天就能用上。

▶ 打开互动版（能点图、做实验、做小测）

🧒 先用大白话说

模型会什么，练好时就定了。想让它多会几样，最省事的办法是递给它说明书、给它装上“手脚”，就像给手机装 App。有三种装法：一个个装工具、接上一整套别人做好的工具（MCP）、给它一包“做法说明”（Skills）。代价是：说明书都要占它的“桌面”（上下文）。

📑 这一站讲了什么

  • 不换模型，也能多会几样
    模型会什么，训练时就定了。要它做新的事，最便宜的办法是在外面“递说明书、接手脚”。三种方式：
  • 🔧 工具：一份说明书 + 一段程序
    一个工具就是一张说明书加一段程序。说明书告诉模型“我叫什么、能做什么、要填哪些信息”；模型想用时写一张“申请单”，程序检查后去真正干活，再把结果告诉模型。说明书要写得一看就懂。
  • 🔌 MCP：工具的“通用插座”
    MCP 像统一的插座：以前每个 AI 应用都要给每个工具单独做一个插头；有了统一插座，工具做一次、应用做一次，就都能插上。但插上一个陌生的插头，就等于信任它，所以只装来源可靠的。
  • 📦 Skills：按需加载的“做法说明”
    一个技能包像一本放在书架上的做法手册：平时只露出书名和一句简介，很省地方；遇到相关的活，助手才把整本拿下来照着做，里面还可以带现成的小程序。
  • ⚠️ 容易混淆：工具 vs MCP vs Skills
    工具像一把螺丝刀，能干一件具体的事；MCP 像墙上的标准插座，各种工具都能插上来用；Skill 像一本操作手册，写着“这种活怎么干”，要干的时候才翻开。
  • ✅ 装一个 MCP 服务器前，先过这张清单
    装一个 MCP 服务器之前，像让陌生人进家门前那样问几句：是谁做的？它要干什么？能看到我的哪些东西？每次用都会问我吗？钥匙是不是给得最少？它读的内容会不会藏着坏指令？
  • 💻 本地模型与开放模型：在自己电脑上跑
    有些模型可以下载到自己的电脑上跑，资料不用离开这台机器，没网也能用。代价是：电脑的内存决定能跑多大的模型，速度一般比不上云端，更新和安全也得自己管。…
